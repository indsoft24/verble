================================================================================
VERBLE — Docker build & deploy (VPS)
================================================================================
Project root:  /var/www/verble.in  (or /var/www/verble)
Compose file:  docker-compose.vps.yml

USE THE SAFE DEPLOY SCRIPT — do NOT run raw `docker compose build` on this VPS.
The server has limited RAM (~4GB, no swap). Unbounded builds can OOM-kill Apache
and take down every site on the host.

--------------------------------------------------------------------------------
SAFE DEPLOY (recommended)
--------------------------------------------------------------------------------

  cd /var/www/verble.in

  # Frontend only (most UI changes) — disconnect-safe:
  nohup ./scripts/deploy-vps.sh web >> /var/log/verble-deploy.log 2>&1 &
  tail -f /var/log/verble-deploy.log
  # Log timestamps are Asia/Kolkata (IST), e.g. [2026-06-28 10:53:06 IST]

  # Backend API only:
  nohup ./scripts/deploy-vps.sh backend >> /var/log/verble-deploy.log 2>&1 &

  # Both (backend first, then web):
  nohup ./scripts/deploy-vps.sh all >> /var/log/verble-deploy.log 2>&1 &

  # Foreground (stay connected):
  ./scripts/deploy-vps.sh web

The script: locks concurrent deploys, caps build RAM/CPU, builds one service at
a time, swaps containers with --no-deps (zero downtime), health-checks, rolls back
on failure, and prunes stale build cache.

--------------------------------------------------------------------------------
WHAT EACH SERVICE IS
--------------------------------------------------------------------------------
  web       Frontend (Vite build + nginx). Rebuild when: React/TS/CSS/i18n changes.
  backend   Node API. Rebuild when: coaching-platform-backend code changes.
  mongo     Database (pre-built image). Rebuild: NEVER for app code. Only `up -d`.
  redis     Cache (pre-built image). Rebuild: NEVER for app code. Only `up -d`.

Apache/cPanel proxies verble.in → host port 3001 (web). No Docker rebuild for
proxy-only fixes — edit Apache userdata proxy.conf and restart httpd.

--------------------------------------------------------------------------------
FIRST-TIME SETUP (no build)
--------------------------------------------------------------------------------

  ./scripts/ready-to-deploy.sh          # secrets + docker compose up -d
  ./scripts/deploy-vps.sh all             # first image build (use nohup on VPS)

--------------------------------------------------------------------------------
RESTART ONLY (no code change)
--------------------------------------------------------------------------------

  docker compose -f docker-compose.vps.yml up -d
  docker compose -f docker-compose.vps.yml up -d backend   # .env change only

--------------------------------------------------------------------------------
STATUS & LOGS
--------------------------------------------------------------------------------

  docker compose -f docker-compose.vps.yml ps
  docker logs -f verble-web --tail 100
  docker logs -f verble-backend --tail 100
  tail -f /var/log/verble-deploy.log
  # Log timestamps are Asia/Kolkata (IST), e.g. [2026-06-28 10:53:06 IST]

--------------------------------------------------------------------------------
WHEN TO USE WHICH
--------------------------------------------------------------------------------
  Change in coaching-platform-frontend/     →  deploy-vps.sh web
  Change in coaching-platform-backend/      →  deploy-vps.sh backend
  Change in both                            →  deploy-vps.sh all
  Server reboot / containers stopped        →  compose up -d
  Only backend .env change (no code)        →  compose up -d backend
  mongo / redis                             →  do NOT build; up -d only if stopped

--------------------------------------------------------------------------------
DO NOT ON PRODUCTION
--------------------------------------------------------------------------------
  docker compose build ...                  →  use deploy-vps.sh instead
  docker compose down -v                      →  deletes database volumes
  docker compose up -d --force-recreate       →  unnecessary downtime / risk

--------------------------------------------------------------------------------
LOCAL DEV (no Docker) — fastest for tiny frontend edits
--------------------------------------------------------------------------------
  cd coaching-platform-frontend && npm run dev
  Uses Vite HMR; changes appear instantly. Use Docker web build only for production.

--------------------------------------------------------------------------------
AFTER DEPLOY
--------------------------------------------------------------------------------
  • Hard refresh browser: Ctrl+Shift+R (Cmd+Shift+R on Mac)
  • Check: curl -sI https://verble.in/ | head -5   (expect 200)
  • Check web:  curl -sf http://127.0.0.1:3001/health
  • Check API:  curl -sf http://127.0.0.1:5001/

--------------------------------------------------------------------------------
SHELL ALIASES (~/.bashrc)
--------------------------------------------------------------------------------
  alias verble-deploy='cd /var/www/verble.in && nohup ./scripts/deploy-vps.sh'
  alias verble-web='cd /var/www/verble.in && nohup ./scripts/deploy-vps.sh web >> /var/log/verble-deploy.log 2>&1 &'
  alias verble-api='cd /var/www/verble.in && nohup ./scripts/deploy-vps.sh backend >> /var/log/verble-deploy.log 2>&1 &'
  alias verble-ps='cd /var/www/verble.in && docker compose -f docker-compose.vps.yml ps'
